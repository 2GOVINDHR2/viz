# Learning Theory → Feature Mapping

The same structure as Table 1 of the CS-OLabs base paper (*"Mapping learning theories to CS-OLabs"*; Swaminathan et al., 2025): three columns, one row per theory. The base paper maps:
- constructivist learning theory → Multi-Visualization Framework and User-Driven Execution Control;
- cognitive load theory → Language-Independent Architecture and Step-by-Step Execution;
- experiential learning theory → Simulation of Real-World Programming Challenges.

Each DL-VizLab row below states what the feature does. Whether it improves learning is the question the study (STUDY-PROTOCOL) answers.

| Educational Theory | DL-VizLab Feature | Description |
|---|---|---|
| **Constructivist Learning Theory** | Multi-view visualisation with learner-driven execution, parameter editing and time travel | Learners build understanding by acting on a real system and reconciling what they predicted with what they observe. **Learner-driven execution:** six step sizes, forwards and backwards, run, run to a breakpoint (`src/core/npm/navigator.ts`, `src/ui/components/Controls.tsx`). **Editing:** starting weights, learning rate, activation, hidden units, loss and batch size (`src/experiments/edits.ts`, *Try it* in `src/ui/components/Guide.tsx`), and the architecture (`src/views/structure/StructureView.tsx`); each change regenerates the run, so the learner sees their own hypothesis played out rather than a canned animation. **Time travel:** stepping back restores the exact earlier state (`reconstructState`, `src/core/npm/state.ts`), so a surprising step can be re-examined. **Misconceptions:** self-check questions with per-option feedback target known misconceptions and gate progression (`src/experiments/registry.ts`, `progress.ts`). |
| **Cognitive Load Theory** | Integrated, synchronised views (split-attention effect) and a graded curriculum with guided walkthroughs (worked-example effect) | **Split attention.** The computation is shown on the network itself: values printed in neurons, weight sign by colour *and* dash, the active instruction highlighted (`src/views/execution/NetworkView.tsx`, `ConvView.tsx`). Beside it, the explanation gives the general formula, the same formula with this step's numbers, and a sentence (`src/explain/`). Views B and C and the inspector follow the same cursor on one screen (`src/ui/App.tsx`), so the learner never matches a separate equation sheet to a diagram. **Worked examples.** Ten experiments ordered from a single neuron to a CNN, each unlocking the next (`src/experiments/registry.ts`). Each walkthrough's "Show me" actions perform the step on the live run, a worked example the learner can hide and resume as guidance fades (`src/ui/components/Guide.tsx`). *Simple* and *detailed* explanation levels address expertise reversal (`src/explain/registry.ts`). Six step sizes let the learner control element interactivity, from one multiplication to a whole epoch. |
| **Experiential Learning Theory** | Training real networks, including on real data, with provoked failures | One pass through Kolb's cycle per experiment. **Concrete experience:** training a real network in the browser, including a CNN on handwritten digits (`src/core/engine/`, experiment 8). **Reflective observation:** "what changed since the previous step" (`src/explain/diff.ts`), the training curves and gradient-magnitude heatmap (`src/views/training/`). **Abstract conceptualisation:** the general formula for every instruction and walkthrough text naming the concept (`src/explain/builtins.ts`). **Active experimentation:** parameter and architecture edits, and breakpoints that stop on a pathology the learner provoked (NaN, exploding or vanishing gradients, dead ReLUs, divergence; `src/core/npm/pathologies.ts`), as in the diagnostic experiments D1 and D2. |
