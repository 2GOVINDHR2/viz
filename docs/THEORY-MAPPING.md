# Learning Theory → Feature Mapping

The same three-column structure as Table 1 of the CS-OLabs base paper (Swaminathan et al., 2025): each learning theory, the DL-VizLab feature that embodies it, and how that feature is implemented. Each row's claim is limited to what the feature does; whether it improves learning is the question the study (STUDY-PROTOCOL) answers.

| Learning theory | Platform feature | Description and implementation |
|---|---|---|
| **Constructivist learning theory** — learners build understanding by acting on a system and reconciling what they predicted with what they observe | Learner-controlled execution with editable parameters and self-checks | Learners choose what to change and observe its consequence in the real computation: starting weights, learning rate, activation, hidden units, loss (`src/experiments/edits.ts`, *Try it* panel in `src/ui/components/Guide.tsx`), and the architecture in View C (`src/views/structure/StructureView.tsx`). Every change regenerates the run, so the learner sees their own hypothesis played out rather than a canned animation. Self-check questions with per-option feedback target known misconceptions and gate progression (`src/experiments/registry.ts`, `progress.ts`). |
| | Bidirectional time travel | Stepping backwards restores the exact earlier state (`stepBackward`, `reconstructState` in `src/core/npm/`), so a learner can re-examine a step that contradicted their expectation instead of re-running from the start. |
| **Cognitive load theory — split-attention effect**: related information should be integrated in space and time rather than spread across sources the learner must mentally combine | Network, numbers, formula and explanation on one screen, synchronised to one cursor | View A shows the computation on the network itself (values printed in neurons, weight sign by colour *and* dash, the active instruction highlighted, `src/views/execution/NetworkView.tsx`, `ConvView.tsx`). Beside it, the explanation shows the general formula, the same formula with this step's numbers, and a sentence (`src/explain/`). Views B and C and the inspector follow the same cursor (`src/ui/App.tsx`). The learner never has to match a separate equation sheet to the diagram. |
| **Cognitive load theory — worked-example effect**: novices learn more from studying worked solutions than from unguided problem solving; guidance should fade as expertise grows | Graded curriculum with guided walkthroughs, and two explanation levels | Ten experiments ordered from a single neuron to a CNN, each unlocking the next (`src/experiments/registry.ts`). Every experiment has a walkthrough whose "Show me" actions perform the step for the learner, a worked example on the live run (`src/ui/components/Guide.tsx`). It can be hidden and resumed, which supports fading. The *simple* and *detailed* explanation levels address the expertise-reversal effect (`src/explain/registry.ts`). |
| | Selectable granularity | Six step sizes (operation → epoch) let a learner control element interactivity: one multiplication at a time when learning the mechanism, whole epochs once it is understood (`src/core/npm/navigator.ts`). |
| **Experiential learning theory (Kolb)** — learning cycles through concrete experience, reflective observation, abstract conceptualisation and active experimentation | One loop through all four stages per experiment | *Concrete experience:* training a real network in the browser and stepping through it (`src/core/engine/`). *Reflective observation:* "what changed since the previous step" (`src/explain/diff.ts`), the training curves and gradient heatmap (`src/views/training/`). *Abstract conceptualisation:* the general formula for each instruction, and walkthrough text naming the concept (`src/explain/builtins.ts`). *Active experimentation:* parameter and architecture edits, breakpoints that stop on a pathology the learner provoked (`src/core/npm/pathologies.ts`), and the diagnostic experiments D1 and D2. |
