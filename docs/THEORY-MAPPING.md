# Learning Theory → Feature Mapping

The same structure as Table 1 of the CS-OLabs base paper (*"Mapping learning theories to CS-OLabs"*; Swaminathan et al., 2025): three columns, one row per theory. The base paper maps:
- constructivist learning theory → Multi-Visualization Framework and User-Driven Execution Control;
- cognitive load theory → Language-Independent Architecture and Step-by-Step Execution;
- experiential learning theory → Simulation of Real-World Programming Challenges.

Each DL-VizLab row below states what the feature does. Whether it improves learning is the question the study (STUDY-PROTOCOL) answers.

| Educational Theory | DL-VizLab Feature | Description |
|---|---|---|
| **Constructivist Learning Theory** | Question-first screens with predict–observe–explain, learner-driven execution, parameter editing and time travel | Learners build understanding by acting on a real system and reconciling what they predicted with what they observe. **Question first (Fix Round 2):** each novice screen opens with one question and one control, and the visualisation grows from the learner's first action (`src/ui/novice/`). **Predict–observe–explain** (White & Gunstone, 1992): before the run, the learner commits to a prediction with one click; the screen then says, from the run's own numbers, whether it held and why (`src/ui/novice/common.tsx`, `state.ts`). The committed prediction creates the conflict that conceptual change works on. **Learner-driven execution:** six step sizes, forwards and backwards, run, run to a breakpoint (`src/core/npm/navigator.ts`, `src/ui/components/Controls.tsx`). **Editing:** starting weights, learning rate, activation, hidden units, loss and batch size (`src/experiments/edits.ts`, *Try it* in `src/ui/components/Guide.tsx`), and the architecture (`src/views/structure/StructureView.tsx`); each change regenerates the run, so the learner sees their own hypothesis played out rather than a canned animation. **Time travel:** stepping back restores the exact earlier state (`reconstructState`, `src/core/npm/state.ts`), so a surprising step can be re-examined. **Misconceptions:** self-check questions with per-option feedback target known misconceptions and gate progression (`src/experiments/registry.ts`, `progress.ts`). |
| **Cognitive Load Theory** | Progressive disclosure on a novice path (split-attention and expertise-reversal effects), integrated synchronised views, and a graded curriculum with guided walkthroughs (worked-example effect) | **Progressive disclosure (Fix Round 2).** The novice path removes extraneous load: one view and one control to start; step sizes offered only once the curriculum has taught them (`src/experiments/surface.ts`); no term before the experiment that teaches it (`src/experiments/vocabulary.ts`); and detail (numbers, maths, a second view) revealed in place where the learner reaches for it. The full three-view workbench is one click away, because scaffolding that helps novices hinders learners who have outgrown it: the **expertise reversal effect** (Kalyuga, Ayres, Chandler & Sweller, 2003). The base paper names adaptive pathways that account for it as the future of CS-OLabs. **Split attention.** The computation is shown on the network itself: values printed in neurons, weight sign by colour *and* dash, the active instruction highlighted (`src/views/execution/NetworkView.tsx`, `ConvView.tsx`). Beside it, the explanation gives the general formula, the same formula with this step's numbers, and a sentence (`src/explain/`). Views B and C and the inspector follow the same cursor on one screen (`src/ui/App.tsx`), so the learner never matches a separate equation sheet to a diagram. **Worked examples.** Ten experiments ordered from a single neuron to a CNN, each unlocking the next (`src/experiments/registry.ts`). Each walkthrough's "Show me" actions perform the step on the live run, a worked example the learner can hide and resume as guidance fades (`src/ui/components/Guide.tsx`). The *Simple*/*Detailed* explanation level is a global default for returning learners, beneath the per-panel reveals (`src/explain/ExplanationPanel.tsx`). Six step sizes let the learner control element interactivity, from one multiplication to a whole epoch. |
| **Experiential Learning Theory** | Training real networks, including on real data, with provoked failures | One pass through Kolb's cycle per experiment. **Concrete experience:** training a real network in the browser, including a CNN on handwritten digits (`src/core/engine/`, experiment 8). **Reflective observation:** "what changed since the previous step" (`src/explain/diff.ts`), the training curves and gradient-magnitude heatmap (`src/views/training/`). **Abstract conceptualisation:** the general formula for every instruction and walkthrough text naming the concept (`src/explain/builtins.ts`). **Active experimentation:** parameter and architecture edits, and breakpoints that stop on a pathology the learner provoked (exploding or vanishing gradients, dead ReLUs, a rising loss; `src/core/npm/pathologies.ts`), as in the diagnostic experiments D1 and D2. NaN/∞ is a safety net that no shipped control can reach (`docs/CONTROL-AUDIT.md`). The novice path's prediction step closes the cycle explicitly: conceptualise → predict → experience the run → reflect on the reveal. |

**References.** White, R. & Gunstone, R. (1992). *Probing Understanding*. Falmer Press (predict–observe–explain). Kalyuga, S., Ayres, P., Chandler, P. & Sweller, J. (2003). The expertise reversal effect. *Educational Psychologist*, 38(1), 23–31.
