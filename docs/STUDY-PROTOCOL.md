# Study Protocol — Evaluating DL-VizLab

**Version 0.1 (draft for ethics submission)** · Prepared 2026-10 · Status: to be reviewed by the research team and supervisor before submission. Items marked **[DECIDE]** need a human decision; every other element has a recommended default.

## 1. Research questions and hypotheses

- **RQ1 (learning).** Does studying neural-network training with DL-VizLab produce greater conceptual learning than studying the same content from static materials (C1) or with an exercise in TensorFlow Playground (C2)?
  - *H1a:* Adjusted post-test scores (pre-test as covariate) differ across conditions.
  - *H1b:* C3 (DL-VizLab) > C1 (static).
  - *H1c:* C3 > C2 (TensorFlow Playground).
- **RQ2 (where).** Which concepts and which levels of understanding (Bloom: recall / understand / apply) account for any difference? Analysed descriptively by concept and level; tested for transfer items.
- **RQ3 (experience).** How usable is DL-VizLab, and at what workload, compared with TensorFlow Playground? (SUS, NASA-TLX raw; C2 vs C3.)
- **RQ4 (engagement).** In C3, which patterns of use (granularity of stepping, time travel, explanation use, breakpoints) are associated with learning gain? Exploratory and correlational.

H1a is the single confirmatory test. H1b and H1c are the planned pairwise contrasts (Holm-corrected). RQ2–RQ4 are secondary or exploratory and will be labelled as such.

## 2. Design

Between-subjects pre-test/post-test randomised experiment with three conditions:

| Condition | Material | Same content? | Same time? |
|---|---|---|---|
| **C1 Control** | Static slides and text covering the curriculum (single neuron → backpropagation → XOR → CNN basics), with the same diagrams as screenshots | Yes | Yes |
| **C2 Baseline** | In-app exercise sheet directing the participant through TensorFlow Playground for the same concepts | Yes (as far as Playground permits; no CNN) | Yes |
| **C3 DL-VizLab** | The full tool, starting at the guided curriculum | Yes | Yes |

**Content parity.** All three conditions follow one shared content outline (the P6 curriculum's learning objectives). C1's slides are generated from the same experiment definitions and explanations as C3, so the information content is held constant and only the medium varies. C2 cannot show CNNs or discrete steps; its sheet covers what Playground supports and points to the static CNN pages from C1 for the rest. This asymmetry is reported as a limitation.

**Two-condition fallback.** If fewer than ~100 participants can be recruited by the cut-off date **[DECIDE: date]**, the study runs C1 vs C3 only, selected in Study Mode's configuration. The confirmatory test becomes H1b with the same ANCOVA model.

**Randomisation.** Study Mode assigns conditions by stratified permuted-block randomisation (block size = number of conditions), stratified on self-rated familiarity with neural networks (1–2 = low, 3–5 = high), collected before assignment. Allocation is concealed until after the demographics stage. A manual override exists for technical recovery only; any use is recorded in the export (`assignment = manual_override`) and reported.

**Blinding.** Participants know their own material but not the hypotheses or the other conditions until debrief. Scoring is automatic. The analyst runs the pre-specified pipeline; condition labels are not needed for any judgement step.

## 3. Participants

- **Population.** Undergraduate or master's students in computing or a related discipline who are taking, or have recently taken, an introductory machine-learning or AI course **[DECIDE: course(s)]**.
- **Inclusion.** Aged 18 or over; able to use a desktop or laptop browser.
- **Exclusion.** Prior participation in a pilot of this study; having completed a dedicated deep-learning course (self-reported). Excluded volunteers may still use the tool afterwards.
- **Recruitment.** Announcement in class and on the course's learning-management system by someone who does not teach or assess the students **[DECIDE: who]**, with the participant information sheet attached. Sessions are booked through an anonymous sign-up slot list.
- **Incentive.** None that depends on performance. **[DECIDE]** whether a small, equal thank-you is offered to every participant regardless of completion.

## 4. Sample size

The confirmatory analysis is a one-way ANCOVA with the pre-test as covariate. Power was computed with `statsmodels` (α = .05, power = .80) and is regenerated by the analysis pipeline (Table 16):

| Design | Effect | Assumed pre–post correlation r | Required N |
|---|---|---|---|
| Three conditions | f = 0.25 (medium) | 0 (ANOVA, no covariate) | 158 |
| Three conditions | f = 0.25 | 0.5 | **119 (40 per condition)** |
| Three conditions | f = 0.25 | 0.6 | 102 |
| Two conditions | d = 0.5 | 0 (t-test) | 128 (64 per condition) |
| Two conditions | d = 0.5 | 0.5 | **98 (49 per condition)** |

A covariate correlated r with the outcome reduces error variance by a factor (1 − r²), so the detectable effect grows by 1/√(1 − r²). Concept-inventory pre/post correlations of around .5 are typical; the realised r is reported. **Target: N = 120 for three conditions (40 per condition), with C1 vs C3 as the fallback if recruitment falls below 100.** With N = 90 the three-condition design has about .67 power for f = 0.25 at r = .5; this will be reported honestly as a limitation if it occurs. The achieved power at the realised effect is reported in Table 16.

## 5. Procedure

One supervised session in a computer lab, run entirely by Study Mode in a browser, with no network access needed.

| Stage | Duration | Content | Recorded |
|---|---|---|---|
| 1. Information and consent | ~5 min | Participant information sheet; explicit opt-in to each statement; decline ends the session | consent flag only |
| 2. Demographics and prior knowledge | ~2 min | Year of study, prior ML course, programming experience, self-rated familiarity (1–5) | `participants.csv` |
| 3. Pre-test | ≤ 15 min, timed | 20-item concept inventory, randomised item and option order, no feedback | `responses_long.csv` with per-item latency |
| 4. Intervention | 30 min fixed **[DECIDE: 30 or 40]** | Condition-specific material; a visible countdown; time-on-task logged | duration; telemetry in C3 |
| 5. Post-test | ≤ 20 min, timed | The same 20 items in a new random order plus 4 transfer items | `responses_long.csv` |
| 6. Questionnaires (C2, C3) | ~5 min | SUS (10 items), NASA-TLX raw (6 items) | `sus.csv`, `tlx.csv` |
| 7. Open feedback | ~3 min | Three prompts: what helped, what was confusing, suggestions | `feedback.csv` |
| 8. Debrief | ~2 min | Purpose of the study, all conditions explained, link to DL-VizLab, participant code | — |

Total ≈ 75–85 minutes. A "Withdraw" button is visible on every screen.

## 6. Instruments

- **Concept inventory** (`src/study/config/concept-inventory.json`): 20 four-option items covering perceptron computation, activation behaviour, forward propagation, loss interpretation, gradient meaning and sign, the chain rule, learning-rate effects, weight-update direction, overfitting, convolution and pooling; each tagged with concept and Bloom level (4 recall, 9 understand, 7 apply). Distractors encode commonly reported novice difficulties. Five transfer items (post-test only) apply the concepts to situations not shown in any condition (dead ReLUs, softmax gradient signs, convolution parameter counts, batch-size effects, symmetric initialisation). Keyed answers to every numerical item are recomputed by the test suite. **The inventory is a draft: it must be piloted** (§10) and reviewed for content validity by at least two instructors.
- **SUS** (Brooke, 1996): standard 10 items, 5-point; scored 0–100 with polarity reversal of even items.
- **NASA-TLX, raw** (Hart, 2006): six 0–100 subscales, unweighted mean.
- **Telemetry** (C3 only): counts and timings of interactions (§7 of `docs/DATA-DICTIONARY.md`); no screen recording, no keystrokes, no free text.

## 7. Analysis plan (pre-specified)

Implemented in `analysis/analysis.py`, validated on simulated data at n = 30, 60 and 120 (`analysis/validate.py`; results skeleton in `docs/RESULTS-SKELETON.md`).

1. **Exclusions.** Withdrawn participants' data are deleted at withdrawal. Participants who do not reach the post-test are excluded from outcome analyses and counted in the flow diagram. No outlier exclusion.
2. **Baseline equivalence.** One-way ANOVA (year, pre-test), χ² (prior ML course, programming experience), Kruskal–Wallis (familiarity). Reported, not used to adjust beyond the pre-registered covariate.
3. **Assumption checks, then test selection.** Shapiro–Wilk on ANCOVA residuals, Levene's test on residuals across conditions, and the condition × pre-test interaction (homogeneity of regression slopes). **If all three hold (p ≥ .05): primary test is the one-way ANCOVA** on post-test with pre-test as covariate (Type II SS), with partial η² and its 95% CI, estimated marginal means with 95% CIs, and Holm-corrected pairwise contrasts with Hedges' g. **Otherwise: primary test is Kruskal–Wallis on gain scores** with ε² and Dunn's tests (Holm). The non-selected analysis is reported as a sensitivity check either way.
4. **Within-condition change.** Paired t-test with d_z and 95% CI, Wilcoxon signed-rank with r, mean individual normalised gain ⟨g⟩ = (post − pre)/(100 − pre), and class-average ⟨g⟩.
5. **Secondary.** Normalised gain by concept and by Bloom level; transfer-item scores by condition; SUS (with adjective and grade) and NASA-TLX for C2 vs C3 (Welch t / Mann–Whitney).
6. **Exploratory.** Spearman correlations between telemetry features and normalised gain in C3, Holm-corrected; reported as associations only.
7. **Reliability.** Cronbach's α (KR-20 for the binary inventory) with Feldt 95% CIs for pre-test, post-test and SUS.
8. **Power.** Achieved power at the observed effect and realised N.

## 8. Data management

- **Anonymity by design.** Study Mode generates a random code (`P-` + 8 base-32 characters) per participant. It never asks for or records names, email addresses, student numbers, IP addresses or device identifiers, and the application makes no network requests. The open-feedback prompts ask participants not to include identifying information; the research team screens `feedback.csv` before any sharing.
- **Storage.** Data stay in the browser's local storage on the study machine until exported at the end of the session by the researcher, then are moved to **[DECIDE: institutional encrypted storage]** and deleted from the study machine. Only the named research team has access.
- **Retention and destruction.** Anonymous data are retained for **[DECIDE: e.g. 5 years after publication, per institutional policy]** and then securely deleted. Consent records contain no names (opt-in flag only).
- **Withdrawal.** In-session withdrawal deletes that participant's responses immediately. After the session, a participant who kept their code may request removal until **[DECIDE: date]**, after which data are included in aggregate analyses.
- **Sharing.** Anonymous, aggregated results will be published; the anonymous dataset may be deposited in an open repository **[DECIDE]**, which the information sheet states.

## 9. Ethical safeguards

- **Power imbalance.** Participants are students; researchers may be connected to their courses. Therefore: recruitment is by someone who does not teach or assess the participants; participation, non-participation, withdrawal and test performance have **no effect on any mark or grade**; teaching staff are not told who took part; individual scores are never reported to anyone; data are anonymous from collection. These points are stated in the information sheet and on the consent form.
- **Control-group fairness.** Participants in C1 and C2 receive full access to DL-VizLab and the same debrief as C3 after the study closes, so no participant is denied the tool's possible benefit. The study takes place outside assessed course time, so no group is disadvantaged in an assessment.
- **Burden.** About 80 minutes in one session; breaks allowed; no deception beyond not stating the hypotheses in advance (fully explained at debrief).
- **Risk.** Minimal: ordinary study activity on a computer.

## 9a. Ethics review: precedent and determination

**Precedent.** The base paper of this research line (Swaminathan et al., *SN Computer Science* 6:284, 2025) reports, in its Ethical Considerations and Declarations sections, that the CS-OLabs study:
- complied with Amrita Vishwa Vidyapeetham's ethical standards;
- *"qualified for exemption under the Indian Council of Medical Research (ICMR) guidelines, which exclude 'comparison of instructional techniques, curricula, or classroom management methods' from review"* (exact wording, verified; Fix Round 1 supplement, S3.3);
- obtained informed consent under ICMR's provisions for exempted research (paraphrased).

**Applicability.** The present study compares three ways of learning the same content (static material, a TensorFlow Playground exercise, DL-VizLab). It is therefore a comparison of instructional techniques and falls within the same clause. Like the CS-OLabs study, it:
- records no identifying data;
- is outside assessed course time;
- lets participants withdraw at any time without consequence;
- gives every participant access to the tool after the study (§9).

**Determination required.** The research team must not self-declare exemption. Before recruitment, the team obtains a **written determination from the institution's ethics committee** stating that the study is exempt, or approving it. The reference is recorded in the consent file (`[[ETHICS_REFERENCE]]`) and in the manuscript. Study Mode will not start while that placeholder is unfilled.

**Draft manuscript paragraph** (to be completed once the determination is issued):

> *Ethical considerations.* The study was conducted in accordance with the ethical standards of Amrita Vishwa Vidyapeetham. As a comparison of instructional techniques, it falls within the categories that the ICMR National Ethical Guidelines for Biomedical and Health Research Involving Human Participants exclude from full review. The Institutional Ethics Committee confirmed this determination in writing ([[APPROVAL REFERENCE]]). Participation was voluntary and did not affect course assessment. No identifying information was collected, participants could withdraw at any point (their data were then deleted), and all participants received access to DL-VizLab after the study.

## 10. Pilot

Before the main study, 5–8 volunteers from outside the target courses complete the full protocol to check timing, item clarity (think-aloud on the inventory), and the export. Items with ceiling or floor effects or confusing wording are revised; pilot data are not analysed with the main data.

## 11. Threats to validity (to be reported)

Novelty effect of an interactive tool; content asymmetry in C2 (no CNNs in Playground); single-session measurement (no retention test); a researcher-developed, unvalidated concept inventory; single institution; possible ceiling effects for students with prior exposure (mitigated by stratification and the covariate).

## 12. Running a session with Study Mode

1. Open the deployed tool with `#study` appended to its address (for example `https://…/#study`) in a normal (not private) browser window on each lab machine.
2. **Session configuration:** study identifier, design (three conditions or the C1 vs C3 fallback), time limits (pre-test, intervention, post-test). The *condition for the next participant* override is for technical recovery only and is recorded as `manual_override`.
3. **Consent text:** load the ethics-approved consent file (same structure as `src/study/config/consent.json`). Study Mode refuses to start while any `[[PLACEHOLDER]]` remains, and rejects files missing required fields.
4. Press **Start a participant session** and hand over the computer. The participant goes through consent → background questions → pre-test → intervention (countdown; ends automatically) → post-test → SUS and NASA-TLX (C2, C3) → comments → debrief with their participant code. *Withdraw* is visible on every screen after consent.
5. When the participant has finished, press **Researcher: end this session**. Repeat.
6. After each block of sessions press **Export data**; the ZIP contains the CSV files described in `docs/DATA-DICTIONARY.md`. Put every machine's export ZIP in one folder and merge them with `python3 analysis/merge_exports.py <folder> <merged_dir>`. The merge checks columns against the data dictionary, refuses colliding participant codes, and writes a manifest of each row's source. Then run `python3 analysis/analysis.py <merged_dir> <output_dir>`.
7. Only after the exports are safely stored, **Delete all study data on this computer**.

C2 opens TensorFlow Playground in a new tab. **C2 uses a pinned local copy** (upstream commit `02469bd`, served from `playground/` with the app; `docs/THIRD-PARTY.md`), so the baseline cannot change version mid-study and works without network access, like C1 and C3. To use the hosted site instead, set `"playground_source": "hosted"` in `src/study/config/playground-sheet.json`. The C1 material is regenerated from the tool with `npm run slides`.
