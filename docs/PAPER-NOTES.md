# Paper Notes (for the authors)

Working notes for the manuscript: what was built, where each claim lives in the code, what was measured, and what can and cannot be claimed. Every number below comes from a generated report and is regenerated by the command given; quote the report rather than this file if they differ.

## 1. The technical contribution as implemented

**The Neural Program Model (NPM).** A training run is compiled into a linear program of typed instructions. Their nesting path (epoch / batch / example / phase / layer) gives the six execution granularities. Their operands are references to earlier results, so data flow is explicit.

The IR is:
- **specified:** `docs/NPM-SPEC.md` gives the data model, grammar, instruction set, file format, extension model, determinism and memory-bounding rules;
- **validated:** a JSON schema is generated from the kind registry, the grammar is checked as a regular language over kinds, and an independent verifier re-derives every instruction (`tools/npm-verify.mjs`);
- **serializable:** lossless, including NaN, ±∞ and −0;
- **replayable:** `tools/npm-replay.mjs`.

Everything the learner sees is rendered from the IR state at a cursor, never from the engine; this is proved by `tests/unit/views-from-trace.test.ts`, which renders all views from a trace file with no engine object. The same IR drives:
- breakpoints and pathology detection;
- explanations: the general formula, the formula with this step's numbers, and a sentence;
- the "what changed" summary;
- figure export;
- Study Mode telemetry, which counts steps per granularity.

**Curriculum on top of the IR.** Ten declarative experiments (`src/experiments/registry.ts`), each verified by a test that trains it and checks the behaviour its objective claims (`tests/unit/experiments.test.ts`).

**Study instrumentation.** Study Mode runs the three-condition study end to end and exports the analysis-ready CSVs defined in `docs/DATA-DICTIONARY.md`. The pipeline that turns them into every table and figure is validated on simulated data.

## 3. Correctness tolerances achieved (`docs/VALIDATION-REPORT.md`, `npm test && npm run report`)

- **Gradient checks:** 35 op cases and 9 whole-model cases. Worst relative deviation from central differences is 1.18 × 10⁻⁶ (tolerance 10⁻⁵, float64, h = 10⁻⁶). A deliberately wrong rule fails, so the check is not vacuous.
- **TF.js parity:** 8/8 architectures (single neuron, linear regression, XOR MLP, softmax with momentum, deep sigmoid, two CNNs, CNN on MNIST) agree on every loss and every parameter after every step for ≥ 100 steps. Worst absolute deviation is 1.04 × 10⁻⁶ (loss) and 1.25 × 10⁻⁶ (parameters); TF.js computes in float32.
- **Determinism:** bit-identical runs, seed-sensitive, identical after resuming from a checkpoint (8/8).

## 4. Measured performance (`npm run measure && npm run report`)

- **Frame rate:** 60 fps while auto-stepping, on both XOR and the CNN.
- **Responsiveness:** generating the CNN trace takes about 8 s in a Web Worker, and the longest main-thread frame meanwhile is 17 ms.
- **CNN memory:** about 81 MB live after garbage collection. The tab's peak resident set is 519–543 MB over seven runs, each with the CNN performance test running alone (no other test in parallel). That is 5–9 % over the brief's ~500 MB budget; see KNOWN-GAPS. (A 679 MB reading from a run in parallel with the whole suite was contention and is excluded; ADR-038.)
- **Trace size:** a full CNN trace has 125 791 instructions (about 729 MB if fully materialised). Checkpointing and LRU recomputation keep it within a 64 MB cache, with recomputation cost measured in NPM-SPEC §9.
- **Scaling:** TRACE-STATISTICS gives instruction counts and how they scale with model size.

Measured in headless Chromium only; the build environment does not permit installing other browsers.

## 5. Limitations to state in the paper

From `docs/LIMITATIONS.md` and `docs/KNOWN-GAPS.md`:
- **Scale:** a CPU, float64 teaching engine; small networks only.
- **Concept inventory:** researcher-developed and not yet piloted; misconception sources are still to be cited.
- **Comparison condition:** TensorFlow Playground cannot show CNNs or discrete steps, so C2 content is asymmetric. C2 also needs network access.
- **Test selection:** Shapiro–Wilk's sensitivity at large n may select the non-parametric primary test; both analyses are always reported.
- **Task analysis:** counts for other tools are analytical and need a second rater.
- **Accessibility:** designed to WCAG 2.1 AA and verified with axe-core on 19 screens (zero violations) plus a manual criterion review; **not yet validated with screen-reader users**, so AA conformance is not claimed. Suggested manuscript wording: *"The interface was designed to WCAG 2.1 AA. An automated audit with axe-core across 19 screens found no violations, and a manual criterion-by-criterion review was carried out; validation with screen-reader users remains future work."*
- **Memory:** peak memory for the CNN sits near the budget.
- **Study Mode:** tested by automation only; a human pilot is still required.
- **Live demo:** depends on enabling GitHub Pages.

**Do not present the simulated results in `docs/RESULTS-SKELETON.md` as findings.** Every table and figure there is watermarked.

## 4a. The novice-path redesign: how to describe it (Fix Round 2)

**Provenance — state it.** The two-path interface followed human testing. The team judged the first full build overwhelming for a beginner ("an ordinary person looking at the cockpit of an aeroplane"), and hand testing found three defects that the presence-only interface tests had missed. Reporting that the design changed in response to testing is a strength of the method, not an embarrassment.

**What to say it is.** A presentation layer over an unchanged engine, IR and trace. All validation evidence is untouched.
- **Novice path (the default):** a purpose-built screen per experiment that opens with a question and one control and grows from the learner's first action. It asks for a prediction before the run and reveals the outcome from the run's own numbers. Detail (numbers, maths, a second view) is offered in place, never forced. Step sizes and vocabulary are unlocked by the curriculum.
- **Expert mode:** the full three-view workbench, one click away, with the position preserved.

**How to frame it.**
- **Theory.** It applies cognitive load theory, which the paper inherits from CS-OLabs. Progressive disclosure targets extraneous load and the split-attention effect, and the one-click expert mode answers the expertise reversal effect (Kalyuga et al., 2003). Predict–observe–explain (White & Gunstone, 1992) is the constructivist and experiential mechanism (THEORY-MAPPING).
- **Lineage.** Swaminathan et al. (2025) name adaptive learning pathways accounting for the expertise reversal effect as the future of CS-OLabs. DL-VizLab's two paths are a first, concrete instance of that future work, and should be presented as a contribution, not a concession.
- **Evidence the paper can cite.**
  - The illumination contract and the declared-surface rule are enforced by tests (`docs/CONTROL-AUDIT.md`: 214 controls audited for observable behaviour; seven defects found, six fixed).
  - Vocabulary gating is enforced by a test that renders every novice screen.
  - The chain-rule panel's product equals the engine's gradient at every step where it is shown.

**What not to claim yet.**
- Only experiments 1, 5 and 6 have novice screens at the 30 October review.
- Whether the novice path increases gains is the study's question, not a result.
- Intervention timings are estimates (STUDY-PROTOCOL §5a).

## 5a. Methodological advance over the base paper's evaluation

State this plainly in the manuscript as a contribution, not left implicit.

**Baseline: the CS-OLabs evaluation** (Swaminathan et al., 2025):
- **Participants:** educators, not students.
- **Samples:** 91 completed the SUS; 63 took the pre-test and 48 the post-test; 25 completed both; the reported analysis sample is 23.
- **Instrument:** 15 items. Mean 7.70 → 9.09; improvement 1.39 (SD 1.59).
- **Tests:** paired *t* = −4.2018, *p* = .0004; Wilcoxon 14, *p* = .0017; sign test 8, *p* = .0001. 73.91 % of participants improved.
- **Usability:** SUS 72.42 (median 75).
- **SUS interpretation differs (Fix Round 2, 7.3).** State this in the manuscript next to any side-by-side SUS comparison: *This study interprets SUS scores with two separately labelled schemes, the nearest Bangor, Kortum & Miller (2009) adjective anchor and the Sauro & Lewis curved grade, whereas the base paper used the SUS Analysis Toolkit of Blattgerste, Behrends & Pfeiffer, whose adjective scale follows Sauro's (2018) reinterpretation; adjective labels are therefore not directly comparable across the two studies, although the numeric SUS scores are* (ADR-036).
- **Not reported:** no control group, no effect sizes, no reliability coefficient, no power analysis.

**The DL-VizLab study** (STUDY-PROTOCOL, `analysis/`):

| | CS-OLabs | DL-VizLab |
|---|---|---|
| Participants | educators | students, the target learners |
| Design | single group pre/post | randomised controlled design with three conditions (static material, TensorFlow Playground, DL-VizLab) or the pre-registered two-condition fallback, stratified on prior knowledge |
| Primary analysis | paired tests | ANCOVA on post-test with the pre-test as covariate, assumptions checked *before* the test is chosen, non-parametric fallback |
| Effect sizes | none | partial η², Hedges' *g* and *d*_z with 95 % confidence intervals |
| Reliability | none | Cronbach's α (with confidence interval) for the 20-item scale and the SUS |
| Power | none | a priori sample size, and achieved power at the realised *n* |
| Gains | — | normalised gain ⟨g⟩, by concept cluster and Bloom level |
| Other outcomes | — | transfer items, NASA-TLX, usage telemetry related to gains |

The pipeline is validated on simulated data at n = 30 / 60 / 120 before any participant takes part.

Report the CS-OLabs figures as the predecessor's evaluation, accurately and without disparagement. The point is that the methodology advances, not that the earlier study was wrong.

## 8a. The gap claim, narrowed (Fix Round 3, B2.2)

**What changed.** The earlier framing implied a gap in *evaluation*: in COMPARISON-MATRIX row 17 (*Measured learning outcome*), every prior system was coded N or L. Together with the narrative above, that reads as "this community does not evaluate its tools or measure understanding". **That is no longer true, and the paper must not say it:**
- Transformer Explainer (CHI 2026) reports a 90-participant study finding advantages in understanding and engagement;
- GNN 101 (IEEE TVCG 2026) was deployed in three university courses and evaluated with teaching assistants and students;
- CS-OLabs, the base paper, reports a paired pre/post measurement.

**The claim that survives, stated as a narrowing.** Use this wording, or something no broader:

> *None of these systems shows the training cycle (the loss, the gradients and the parameter updates of a run) as discrete, inspectable steps, and none provides a formally specified, independently verifiable representation of that cycle. Studies of these tools have measured understanding, engagement and usability; none, to our knowledge, reports a controlled comparison of learning gain against an alternative condition. This paper's contribution is the representation; the controlled learning-gain study is designed and instrumented but not yet run.*

- **Two of the three parts are about the system**, and they are what COMPARISON-MATRIX rows 9, 11, 12 and 14 show.
- **The third part is narrow on purpose.** A study of understanding is not a controlled learning-gain comparison, but DL-VizLab has not run one either. It is a statement about the literature, not a result of this paper.
- **To check before submission:** Transformer Explainer's full paper. If its 90-participant study had a comparison condition and measured gain, drop the third part.
- **Where it changed.**
  - The matrix row is relabelled *Controlled learning-gain study*, with a note listing what each system did evaluate (COMPARISON-MATRIX footnote ⁴).
  - DL-VizLab's own cell moves from L to N: it has not run one.
