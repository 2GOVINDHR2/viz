# Paper Notes (for the authors)

Working notes for the manuscript: what was built, where each claim lives in the code, what was measured, and what can and cannot be claimed. Every number below comes from a generated report and is regenerated by the command given; quote the report rather than this file if they differ.

## 1. The technical contribution as implemented

**The Neural Program Model (NPM).** A training run is compiled into a linear program of typed instructions. Their nesting path (epoch / batch / example / phase / layer) gives the six execution granularities. Their operands are references to earlier results, so data flow is explicit.

The IR is:
- **specified:** `docs/NPM-SPEC.md` gives the data model, grammar, instruction set, file format, extension model, determinism and memory-bounding rules;
- **validated:** a JSON schema is generated from the kind registry, the grammar is checked as a regular language over kinds, and an independent verifier re-derives every instruction (`tools/npm-verify.mjs`);
- **serializable:** lossless, including NaN, ±∞ and −0;
- **replayable:** `tools/npm-replay.mjs`.

Everything the learner sees is rendered from the IR state at a cursor, never from the engine; this is proved by `tests/unit/views-from-trace.test.ts`, which renders all views from a trace file with no engine object. The same IR drives:
- breakpoints and pathology detection;
- explanations: the general formula, the formula with this step's numbers, and a sentence;
- the "what changed" summary;
- figure export;
- Study Mode telemetry, which counts steps per granularity.

**Curriculum on top of the IR.** Ten declarative experiments (`src/experiments/registry.ts`), each verified by a test that trains it and checks the behaviour its objective claims (`tests/unit/experiments.test.ts`).

**Study instrumentation.** Study Mode runs the three-condition study end to end and exports the analysis-ready CSVs defined in `docs/DATA-DICTIONARY.md`. The pipeline that turns them into every table and figure is validated on simulated data.

## 3. Correctness tolerances achieved (`docs/VALIDATION-REPORT.md`, `npm test && npm run report`)

- **Gradient checks:** 35 op cases and 9 whole-model cases. Worst relative deviation from central differences is 1.18 × 10⁻⁶ (tolerance 10⁻⁵, float64, h = 10⁻⁶). A deliberately wrong rule fails, so the check is not vacuous.
- **TF.js parity:** 8/8 architectures (single neuron, linear regression, XOR MLP, softmax with momentum, deep sigmoid, two CNNs, CNN on MNIST) agree on every loss and every parameter after every step for ≥ 100 steps. Worst absolute deviation is 1.04 × 10⁻⁶ (loss) and 1.25 × 10⁻⁶ (parameters); TF.js computes in float32.
- **Determinism:** bit-identical runs, seed-sensitive, identical after resuming from a checkpoint (8/8).

## 4. Measured performance (`npm run measure && npm run report`)

- **Frame rate:** 60 fps while auto-stepping, on both XOR and the CNN.
- **Responsiveness:** generating the CNN trace takes about 8 s in a Web Worker, and the longest main-thread frame meanwhile is 17 ms.
- **CNN memory:** about 81 MB live after garbage collection. The tab's peak resident set is 456–544 MB, around the brief's ~500 MB budget; see KNOWN-GAPS.
- **Trace size:** a full CNN trace has 125 791 instructions (about 729 MB if fully materialised). Checkpointing and LRU recomputation keep it within a 64 MB cache, with recomputation cost measured in NPM-SPEC §9.
- **Scaling:** TRACE-STATISTICS gives instruction counts and how they scale with model size.

Measured in headless Chromium only; the build environment does not permit installing other browsers.

**Filling the Firefox, Edge and WebKit rows** (about ten minutes on any team member's laptop; Edge needs Windows, macOS or a Linux machine where `msedge` can be installed):


## 5. Limitations to state in the paper

From `docs/LIMITATIONS.md` and `docs/KNOWN-GAPS.md`:
- **Scale:** a CPU, float64 teaching engine; small networks only.
- **Concept inventory:** researcher-developed and not yet piloted; misconception sources are still to be cited.
- **Comparison condition:** TensorFlow Playground cannot show CNNs or discrete steps, so C2 content is asymmetric. C2 also needs network access.
- **Test selection:** Shapiro–Wilk's sensitivity at large n may select the non-parametric primary test; both analyses are always reported.
- **Task analysis:** counts for other tools are analytical and need a second rater.
- **Accessibility:** designed to WCAG 2.1 AA and verified with axe-core on 19 screens (zero violations) plus a manual criterion review; **not yet validated with screen-reader users**, so AA conformance is not claimed. Suggested manuscript wording: *"The interface was designed to WCAG 2.1 AA. An automated audit with axe-core across 19 screens found no violations, and a manual criterion-by-criterion review was carried out; validation with screen-reader users remains future work."*
- **Memory:** peak memory for the CNN sits near the budget.
- **Study Mode:** tested by automation only; a human pilot is still required.
- **Live demo:** depends on enabling GitHub Pages.

**Do not present the simulated results in `docs/RESULTS-SKELETON.md` as findings.** Every table and figure there is watermarked.
